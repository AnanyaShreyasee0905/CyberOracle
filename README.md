# CYBER-ORACLE — Predictive Cyber Defence Using a Network World Model

A working prototype: synthetic multi-stage attack data → a GNN+temporal
world model (pure NumPy, no GPU/heavy deps needed) → K-step forward risk
forecasting → MITRE ATT&CK stage mapping → a **counterfactual defence
simulator** (test "isolate this host" before doing it for real) → a
SOC-style React dashboard.

Everything in this repo has been run and verified end to end: gradient
checks, training, all five API endpoints, and a production frontend
build. See `docs/build-notes.md` for exactly what was tested and what
tradeoffs were made under hackathon time constraints — read that before
your pitch, it tells you what to say if a judge asks "why not real
PCAP data" or "why NumPy instead of PyTorch."

## Quick start (two terminals)

### 1. Generate data + train the model (run once)

```bash
cd ml
python3 -m venv .venv          # optional but recommended
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install numpy

cd ../data/scripts
python3 generate_synthetic_data.py     # writes data/processed/episodes.json

cd ../../ml
python3 train.py                        # trains + writes checkpoints/world_model.npz
                                         # and data/processed/demo_episode.json
```

This takes a few seconds (it's a tiny NumPy model, not a multi-GB training job).

Optional: verify the hand-written backprop against numerical gradients:
```bash
python3 _gradcheck.py     # should print "Gradient check PASSED"
```

### 2. Start the backend (Terminal 1)

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python3 -m uvicorn app.main:app --reload --port 8000
```

Visit http://127.0.0.1:8000/ — you should see `{"status":"ok",...}`.
Interactive API docs: http://127.0.0.1:8000/docs

### 3. Start the frontend (Terminal 2)

```bash
cd frontend
npm install
npm run dev
```

Visit http://127.0.0.1:5173/ — the dashboard should load and show the
network graph, trajectory timeline, and counterfactual controls.

If your backend runs on a different host/port, set `VITE_API_URL`
before `npm run dev` (e.g. `VITE_API_URL=http://127.0.0.1:8000`).

## What you'll see

- Drag the **window scrubber** to move through the 24-window episode.
  Watch the risk score climb through reconnaissance → credential access
  → lateral movement → exfiltration, then drop back to baseline.
- The **network graph** shows the attacker (red) and the compromised
  host (orange) as the attack progresses.
- The **trajectory chart** shows the observed risk (solid blue) plus a
  6-step forecast (dashed orange) generated by rolling the model's own
  predictions forward.
- The **counterfactual simulator**: pick "Isolate host" at, say, window
  9 (credential access) — the "with intervention" curve stays under
  45% instead of climbing to 80%+. Try the same thing at window 13
  (exfiltration already underway) — the two curves barely diverge. This
  contrast is genuinely useful in the pitch: it shows *when* intervention
  still matters.

## Swapping in real data later

Everything downstream of `data/scripts/flows_to_windows.py` only cares
about one contract: a list of windows, each with an `edges` list of
`[src_host, dst_host, {bytes, conns, ports, syn_ratio}]`. If you get
CICIDS2017/UNSW-NB15 CSVs, write an adapter that groups flows into time
buckets and emits that same structure — training, rollout, counterfactual,
and the dashboard all work unchanged.
